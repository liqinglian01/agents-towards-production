# 固定骨架 vs 固定骨架 + 自主格子

> 📄 English: *(this tutorial is Chinese-only)*

一个**可运行的对比实验**，用来回答一个具体问题：

> 既然 LangGraph 的 `StateGraph` 是「人写死的流程图」，
> 那它和「让 Agent 自主判断」到底怎么协同？

答案是：**不是二选一，而是「固定骨架里留几格给自主」。** 这个项目把同一套报销审核业务写成两版，跑同一批单据，把差异摆在一起看。

---

## 一、核心设计：两版只差一个函数体

这是本实验最想说清楚的一点 ——

```
expense_common.py  ← 两版【完全共用】
├─ LLM 配置
├─ ExpenseState 定义
├─ 5 个节点中的 4 个（校验 / 分类 / 生成意见 / 审批人）
├─ 2 个路由函数
└─ build_graph(check_fn)   ← 图本身也只写一次

version_a_fixed.py   ──┐
version_b_hybrid.py  ──┴─→ 各自只提供「核对」这一个节点的函数体
```

两版组装图时都是：

```python
app = build_graph(check_expense)   # 换掉这一个函数，图完全不变
```

- **A 版**：`check_expense` 内部 = **一次 LLM 调用**（把单据文本丢给模型判断）
- **B 版**：`check_expense` 内部 = **一个 `create_agent`**（自己决定去查哪些系统、查几次）

**图的形状、State、路由规则、其他四个节点，一行都没改。**

这就是协同的接口：自主 Agent 被「关在格子里」——

| | |
|---|---|
| **入口确定** | 只能从 `State` 读数据（图给的） |
| **出口确定** | 只能返回一个 dict 写回 `State`（图收的） |
| **边界确定** | 能用哪些工具由人定（`expense_common.TOOLS`） |

## 二、快速开始

```bash
cd tutorials/fixed-vs-autonomous-expense

# 1. 装依赖
pip install -r requirements.txt

# 2. 配置 key
cp .env.template .env
# 编辑 .env 填入你的 key（默认指向 OpenAI 兼容网关）

# 3. 跑对比
python compare.py
```

也可以单独跑某一版看细节：

```bash
python version_a_fixed.py     # 只看固定版
python version_b_hybrid.py    # 只看自主版
```

## 四、测试数据埋的坑

关键设计：**有些问题单据文本里看不出来，只有真的发起查询才能发现。**

| 单据 | 报销单上写的 | 藏在「后端系统」里的真相 |
|---|---|---|
| **单据 1 · 差旅** | 行程单号 TRIP-889，住宿 3 晚 2400 元 | 行程单实际只有 **2 天**（3/11–3/12）；且单价 800 元/晚 > 标准 400 元 |
| **单据 2 · 采购** | 采购单号 PO-2024-0156，金额 8600 元 | 该采购单批复额度**只有 5000 元**，超标 3600 元 |
| **单据 3 · 招待** | 招待 4 人，人均 200 元 | 没有坑 —— 信息自足，**故意留一个对照组** |

A 版只能看到左列，B 版能去查右列。

## 五、实测结果

```
  单据                  A 问题数    B 问题数   A 代价          B 代价
  --------------------------------------------------------------------
  单据 1 · 差旅               0        3   4LLM/0工具      6LLM/4工具
  单据 2 · 采购               0        2   4LLM/0工具      5LLM/4工具
  单据 3 · 招待               0        0   4LLM/0工具      5LLM/2工具
```

### 单据 1（差旅）

- **A 版**：`合规`。它的依据是「3600 = 2400 + 1200，算得对，事由与类别一致，未发现异常」—— **完全被单据文本骗过去了**
- **B 版**：`不合规`，查出 3 个问题。它自己决定调了 `query_trip` / `query_policy` / `query_history`，发现：
  - 行程单是 2 天，但住宿报了 3 晚
  - 住宿单价 800 元/晚，超 400 元标准
  - 报销人张伟上季度已有 1 笔住宿超标被驳回的记录

### 单据 2（采购）

- **A 版**：`合规`。依据是「有采购单号、有订单号、金额前后一致」—— **看到单号就以为合规了**
- **B 版**：`不合规`。它查了 `query_approval`，发现批复额度只有 5000 元，超标 3600 元。
  **额外收获**：它还自己交叉对比出「采购单申请人是张伟，报销人是李娜」这个我没埋进去的不一致 —— 这是它把两个独立查询结果放在一起比出来的。

### 单据 3（招待）

- **两版都是 `合规`**，结论一致
- B 版仍然花了 2 次工具调用去核实（`query_policy` / `query_history`）

## 六、怎么读这个结果

### ① 自主的价值：能「去查」

A 版和 B 版拿到的**输入完全相同**，差别只有一个：**能不能发起查询**。

A 版是在「凭单据文本猜」，无论 prompt 写得多好，它都只能基于已给的信息推理。B 版是在「先查清事实，再下判断」。

**这个差别在真实业务里就是「漏判」和「查出来」的差别。**

### ② 自主的代价：不是免费的

看单据 3 —— **信息自足的场景里，两版结论一样，B 版白花了调用。**

关于成本，这里有一个**诚实的观察**：在这个 demo 里，B 版的 LLM 调用次数只比 A 版多 1–2 次（比值约 1.2 倍），没有想象中悬殊。原因是**固定骨架本身已经占了 4 次 LLM 调用**（校验、分类、核对、生成意见），自主 Agent 多出来的那点被摊薄了。

真正的差别其实在别处：

| 维度 | 差异 |
|---|---|
| **工具调用** | A 版 0 次，B 版 2–4 次（这部分在真实系统里是网络 IO + 外部系统压力） |
| **结论质量** | 3 张单子里 B 多查出 5 个问题（这是主要收益） |
| **可预测性** | A 版每次跑结果几乎一样；B 版每次查什么、查几次可能不同 |

所以务实的结论不是「自主一定更好」，而是：

> **自主的成本是可接受的，收益是「去查」的能力 —— 前提是这一步确实需要查。**

### ③ 什么时候该放自主

| 放**固定**节点里 | 放**自主**格子 里 |
|---|---|
| 流程有哪几步、什么顺序 | 某一步**内部**怎么查 |
| 分类 / 路由规则 | 查哪些系统、查几轮 |
| 成本预算（哪步用便宜模型） | 具体怎么组合工具 |
| 危险动作的审批关卡 | 信息收集、交叉验证 |
| 合规必经环节 | —— |

一句话：**「不能出错 / 要算钱 / 要留痕」的放固定；「情况多变、规则写不完」的放自主。**

## 七、动手改一改

想验证「协同」到底有多松耦合，可以试这几个改动：

1. **把 B 版的工具减少到 1 个**（只留 `query_approval`）→ 看单据 1 还能不能查出问题。
   *体会：自主 Agent 的能力边界是「你给它什么工具」定的，不是它自己长的。*

2. **把 A 版和 B 版对调**：让 A 版用自主、B 版用固定。
   *体会：图完全不知道里面换人了。*

3. **给 B 版的 Agent 加一句「查不到就说不确定」**，再看单据 3。
   *体会：自主节点的行为调节，是通过它的入口 prompt 和工具集，不用动图。*

4. **把 `check_expense` 前后各插一个节点**（比如「合规校验」和「人工审批」）。
   *体会：这也正是 `arcade-secure-tool-calling` 教程里 `interrupt` 人工审批卡在自主 Agent 后面的用法。*

## 八、与仓库其他教程的关系

| 教程 | 自主度 | 说明 |
|---|---|---|
| `LangGraph-agent` | L1 | 手写条件路由，LLM 只当开关 |
| **本项目 A 版** | **L1** | 同形态，业务换成报销审核 |
| **本项目 B 版** | **L2** | 骨架固定 + 核对节点自主 |
| `agent-memory-with-redis` | L2 | 外层 StateGraph 包一个 `travel_agent`，同样的混合模式 |
| `arcade-secure-tool-calling` | L2 | 自主 Agent + `interrupt` 人工审批关卡 |
| `agent-with-tavily-web-access` | L3 | 整张图交给 `create_agent`，全自主 |

建议先读 `LangGraph-agent`（理解图/State/节点），再看本项目（理解协同），最后看 L3 那几个（理解全自主的边界）。

## 九、注意

- `.env` 已被 `.gitignore` 忽略，**不会进提交**。提交前请确认你的 key 没有被硬编码进任何 `.py` 文件。
- mock 数据（`APPROVALS` / `ORDERS` / `TRIPS` / `POLICY` / `HISTORY`）都写在 `expense_common.py` 里，纯本地，不依赖任何外部服务。
- 本教程为了演示「自主格子」，让 Agent 每次运行都**新建**一个（`check_expense_autonomous` 内部 `create_agent`）。生产环境应把这个 agent 建在模块级别复用，避免重复初始化开销。
