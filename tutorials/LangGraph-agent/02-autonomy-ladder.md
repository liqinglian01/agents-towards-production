# 02 · 自主度阶梯：固定和自主怎么协同

## 一句话

**不是二选一。是「固定骨架里留几格给自主」。**

---

## 阶梯

| 级别 | 谁做决定 | 形态 | 仓库里的例子 |
|---|---|---|---|
| **L0** | 代码 if-else | 纯 Python 节点 | 本项目的 `notify_director` |
| **L1** | LLM 决定 **一次** | 节点内一次 LLM 调用 / 条件边 | [`langgraph_tutorial-zh.ipynb`](langgraph_tutorial-zh.ipynb) |
| **L2** | 图定位置，LLM 在 **格子内**自主 | 一个 `create_agent` 塞在节点里 | 本项目 B 版、[`agent-memory-with-redis`](../agent-memory-with-redis/) |
| **L3** | **整张图** 交给 Agent | 直接 `create_agent`，没有手写的图 | [`agent-with-tavily-web-access`](../agent-with-tavily-web-access/) |

**级别越高 ≠ 越好。** 每一级都是拿「可控性」换「灵活性」。

---

## L0 —— 能写成代码的，就别给 LLM

```python
def route_by_amount(state):
    return "director" if float(state.get("amount", 0) or 0) > 5000 else "manager"
```

100% 确定、不花钱、不可能出错。

**每找到这样一个节点，你就省一次调用、去掉一个不确定源。**

判断标准：这件事 **能穷举** 吗？金额比大小能，语义理解不能。

---

## L1 —— LLM 决定一次

```python
def classify_expense(state) -> dict:
    r = llm_json(f"判断这张报销单的类别...{state['receipt_text']}")
    return {"expense_type": ..., "amount": ...}
```

输入固定、输出固定、**一次调用就结束**。适合：分类、抽取、摘要、写文案。

### 加固技巧：LLM 判完，代码再校验一遍

```python
etype = str(r.get("type", "unknown")).strip().lower()
if etype not in ("travel", "purchase", "entertainment"):
    etype = "unknown"          # LLM 乱答 → 修正
```

**能穷举的输出，就一定要有代码兜底。**

---

## L2 —— 图定位置，LLM 在格子内自主 ← 混合模式

这一格内部 **不再是一次调用，而是一个循环**：

```
┌─ 节点 check_expense ─────────────────────────┐
│                                              │
│    ┌─→ LLM：想 → 出 tool_calls ─┐            │
│    │                            ↓            │
│    │      执行工具（本地代码，不耗 LLM）        │
│    │                            │  ← 循环    │
│    └──────── 拿到结果，再想 ←────┘            │
│                  ↓                           │
│              信息够了 → 出最终结果            │
└──────────────────────────────────────────────┘
```

代码上就是一个 `create_agent` 放在节点里（[version_b_hybrid.py:40](../fixed-vs-autonomous-expense/version_b_hybrid.py#L40)）。

### 这就是「协同」的答案 —— 自主 Agent 被关在格子里

| | |
|---|---|
| **入口确定** | 只能从 State 读数据（图给的） |
| **出口确定** | 只能返回一个 dict 写回 State（图收的） |
| **边界确定** | 能用哪些工具由 **人** 定 |

它可以在格子里随便折腾，但 **越不出这个格子**。而格子外面（谁先谁后、怎么分叉、谁审批）全是人钉死的。

---

## L3 —— 全自主

整张图交给 `create_agent`，不手写节点。

灵活度最高，**可控性最低** —— 你没法保证它一定先查审批单再下结论、没法保证它不跳过某步、成本也没法预估。

| | |
|---|---|
| **什么时候选** | 任务本身没法拆成固定阶段（开放式研究、复杂排查） |
| **什么时候别选** | 流程有明显阶段、且某些阶段必须钉死 → 用 L2 |

---

## 固定 vs 自主：放哪一格

| 放 **固定** 格子 | 放 **自主** 格子 |
|---|---|
| 流程有哪几步、什么顺序 | 某一步 **内部** 怎么查 |
| 分类 / 路由规则 | 查哪些系统、查几轮 |
| 成本预算（哪步用便宜模型） | 具体怎么组合工具 |
| 危险动作的审批关卡 | 信息收集、交叉验证 |
| 合规必经环节 | —— |

一句话：

> **「不能出错 / 要算钱 / 要留痕」的放固定；「情况多变、规则写不完」的放自主。**

## 判断依据的权威性阶梯

这一节回答另一个问题：**节点下判断时，依据是从哪来的？**

同样是「判断」，依据的可靠性差着数量级：

| 级别 | 依据来源 | 可靠性 | 例子 |
|---|---|---|---|
| 1 | **纯代码 if-else** | 100% | `金额 > 5000 → 总监` |
| 2 | **人工写进 prompt 的规则** | 确定，但 LLM 可能不遵守 | 「compliant 为 false 就必须驳回」 |
| 3 | **工具查回来的事实** | 权威（前提是工具真接了系统） | 查审批系统得「额度 5000」 |
| 4 | **模型自己的世界常识** | ❌ 最不可靠 | 「住宿 3 晚，看起来还行」 |

### 第 4 级为什么危险

因为它 **错的时候说话最像对的**。

配套项目 A 版三张单子全部判「合规」，它给的理由是：

> 「3600 = 2400 + 1200，算得对，事由与类别一致，未发现异常」

读起来非常专业。但那份专业感是 **用流利的语言掩盖了没有依据** —— 它没查过行程单、没看过报销标准，那句「未发现异常」的真实含义只是：

> **「我没有信息去发现异常。」**

### 设计启示

**做节点设计时，对每一格问一句：它的判断依据是第几级？**

| 如果答案是 | 该做什么 |
|---|---|
| 第 1 级 | 别用 LLM，直接写代码 |
| 第 2 级 | 可以，但要意识到「硬性规则」其实是软的，要在下游兜底 |
| 第 3 级 | 理想状态 |
| 第 4 级 | ⚠️ **危险信号**。要么给它工具升到第 3 级，要么明确接受「它就是在猜」并让下游有人工复核 |

### 一个反直觉的点

**`temperature=0.0` 只保证「稳定」，不保证「正确」。**

A 版是 **稳定地错** —— 跑三次，三次都判合规。

## 成本：自主不是免费的

用配套项目的实测数据（`python compare.py`）：

```
  单据               A 问题数   B 问题数    A 代价         B 代价
  单据 1 · 差旅          0        3      4LLM/0工具     6LLM/4工具
  单据 2 · 采购          0        2      4LLM/0工具     5LLM/4工具
  单据 3 · 招待          0        0      4LLM/0工具     5LLM/2工具
```

**一个诚实的观察**：LLM 调用只多了 1–2 次（约 1.2 倍），没有想象中悬殊。原因是 **固定骨架本身已经占了 4 次 LLM 调用**（校验 / 分类 / 核对 / 生成意见），自主多出来的那点被摊薄了。

真正的差别在别处：

| 维度 | 差异 |
|---|---|
| **工具调用** | A 版 0 次，B 版 2–4 次（真实系统里这是网络 IO） |
| **结论质量** | 3 张单子里 B 多查出 5 个问题 |
| **可预测性** | A 版每次结果几乎一样；B 版每次查什么、查几次可能不同 |

还有 **单据 3** —— 没有坑、信息自足，两版结论一样，**B 版白花了 2 次工具调用**。

所以务实的结论不是「自主一定更好」，而是：

> **自主的成本是可接受的，收益是「去查」的能力 —— 前提是这一步确实需要查。**

---

## 本章小结

- 自主度是 **阶梯**（L0 → L3），不是开关
- **L0 是最容易被忽略的省钱机会**：能写代码的别给 LLM
- L2 混合模式的接口是「入口 / 出口 / 边界 三重确定」
- 判断依据分四级，**第 4 级（模型常识）最危险，因为它错得像对的**
- 自主有成本，且 **不保证有收益** —— 信息自足的场景里它是纯浪费
